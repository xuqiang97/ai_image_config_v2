# M-38092【AI生图】[美工+运营]管理员配置二期优化

禅道需求：<https://pm.zhcxkj.com/zentao/story-view-38092.html>

GitHub PRD（已发布版本）：<https://github.com/xuqiang97/ai_image_config_v2>

在线原型（已发布版本）：<https://xuqiang97.github.io/ai_image_config_v2/>

## 需求概述

一期在个人模型配置中维护 appKey，人员调岗后需要人工更新，容易产生费用归属错误；多个小组共用凭据时，原来的按 appKey 批量修改无法准确区分小组，业务管理页面也会暴露完整凭据。

本期覆盖美工、运营管理员配置及相关生图任务：**部门决定新任务使用的生图凭据，用户配置决定生图资格与额度，已提交任务继续使用发起时的凭据。** 复用现有组织数据与任务流程，业务管理员维护人员和额度，授权研发维护部门凭据。以下七个重点与功能需求第 1～7 节一一对应。

| 核心重点 | 本期规则 |
|---|---|
| 1. 人员与部门归属 | `userId` 对应 `rb_admin.ID`，所属部门取 `rb_admin.DepartmentID`；按部门选人、批量范围和凭据匹配使用同一归属，兼管部门不改变个人归属。 |
| 2. 部门凭据匹配与维护 | 按模型分别配置部门凭据，本部门优先、逐级继承最近有效上级配置；允许多个部门共用凭据，保留已有任务需要的历史凭据。 |
| 3. 用户配置与额度管理 | 保留用户级授权、quota 和启停；调岗不自动开通、启用或重置额度，同部门人员可有不同额度。 |
| 4. 新旧任务与异常处理 | 首次实际对外提交时实时查询当前部门，已提交任务固定部门与凭据快照；部门或凭据异常时判失败、记录原因并进入「已完成」。 |
| 5. 管理页面查询与个人配置 | 美工、运营保持独立页面及数据范围；移除 appKey 入口，从全公司组织树多选人员。人员额度配置保存不因部门或凭据异常增加预检、告警或阻断。 |
| 6. 按部门批量更新 quota | 从全公司组织树多选部门，支持父子联动，按当前页面、最终勾选部门范围及模型整份覆盖已有配置的 quota；范围去重，包含停用配置，保留启停，不自动新增员工配置。 |
| 7. 权限与上线边界 | 沿用既有权限，业务端不暴露凭据；先上线部门映射表，再完成本系统与对话生图项目的生产切换，最后弃用或删除用户配置表 appKey，并保留历史任务所需凭据。 |

优先保证部门费用归属正确、已提交任务可继续查询，以及业务端不泄露凭据；部门批量额度功能目标同期完成。具体接口、存储和任务实现由研发确定，产品行为与验收以本文为准。

## 原型使用说明

原型使用虚构人员、部门及额度，不连接真实接口。可在线查看，也可下载 [index.html](index.html) 后用浏览器打开，无需安装依赖；所有修改仅在当前页面生效，刷新恢复。

本地评审以本目录的 `README.md` 与 `index.html` 为准；顶部线上链接对应已发布版本，本地修改发布后才会同步。原型内的【当前 PRD】链接指向同目录文档。

- 默认入口：顶部设【本期前端改动】【美工管理员配置】【运营管理员配置】三个 tab，默认打开【本期前端改动】，对照展示移除 appKey、配置用户树形查询、批量模型改为必选三项改动，下方提供简要交互说明和虚构演示工号。
- 演示切换：美工、运营两个 tab 直接展示最终业务界面，切换后恢复对应页面的默认查询状态；正式产品仍保留两个独立入口和各自配置范围。
- 体验顺序：查看前端改动对照 → 切换业务页面 → 配置用户按部门整组选人、取消个别人 → 单人新增、查看、编辑 → 部门多选联动批量覆盖额度 → 对照另一业务页面。可体验成功、无匹配、输入错误及部门缺失场景。

【本期前端改动】及演示导航、样例仅用于原型评审，不是正式系统新增的业务入口。任务凭据、异常处理和跨项目上线顺序见下文功能需求；真实生图、费用、组织查询、凭据匹配及快照、网络故障和组织变动需由研发实现后验收。

## 功能需求

### 1. 人员与部门归属

| 关联项 | 规则 |
|---|---|
| 生图用户ID | 生图配置的 `userId` 对应 `rb_admin.ID`，不是员工工号。 |
| 用户部门归属 | 通过用户ID取得 `rb_admin.DepartmentID`，关联 `rb_department.ID` 获取部门详情；上级关系使用 `rb_department.ParentID`。 |
| 使用范围 | 按部门选人、批量配置范围及新任务凭据匹配，统一以员工的 `DepartmentID` 为所属部门依据。 |
| 兼管部门 | `rb_department.LeaderID` 表示部门负责人，不用于判断个人归属；兼管其他部门不会自动将该员工纳入那些部门的人员节点或批量范围。 |

组织归属及更新时效由现有组织系统负责，本期按查询时的记录处理，不新增组织同步机制或同步时效指标。部门改名不改变筛选、匹配所指向的正式部门，也不影响人员新任务匹配；初始部门数量不限制后续新增部门。

### 2. 部门凭据匹配与维护

- 按生图模型分别配置，同模型、同部门同时只能有一个有效配置；特殊部门可独立配置。
- 多个部门允许共用同一凭据，不能据此认定人员属于同一部门。
- 本期涉及 LinkFox、自研以及已停用的阿里绘蛙历史配置；后者仅保留历史配置和任务处理能力，不恢复新任务。
- 部门凭据由授权研发低频、受控维护并保留变更记录，业务管理员无查看和维护入口。
- 凭据变更不得覆盖或删除仍被任务使用的历史凭据；已有任务按第 4 节继续使用原凭据。

新任务按查询到的当前部门和生图模型匹配：本部门有有效配置时优先使用，否则沿组织父级逐级向上，使用最近的有效配置。不跨兄弟部门寻找，也不通过相同凭据反推个人归属。查询时点、无有效匹配及配置异常的处理统一见第 4 节。

例如：美工一组、美工二组未单独配置时，使用创意设计部的凭据；美工一组配置独立凭据后优先使用自己的配置。IT 部可与销售部共用凭据，其下属产品组、测试组仍按同一继承规则处理。

### 3. 用户配置与额度管理

- 当前业务页面内，同一用户、同一模型只保留一条配置。
- 没有配置、配置停用或额度不足，均按现有规则拒绝生图；部门存在有效凭据不等于人员获得授权，新人仍需管理员手动新增配置。
- 调岗不自动改变用户启停和个性化 quota；同部门不同人可以有不同 quota，并可单独维护。
- 剩余额度、用量、扣减及重置沿用既有口径。

美工、运营配置列表的 quota 表头右侧沿用现有问号图标，鼠标悬停时以深色浮层显示以下文案：

```text
quota 为模型额度配置，字段口径如下：
total：总额度
scene：场景图额度
closeUpWhite：白特图额度
closeUp：特写图额度
sellPoint：卖点图额度
aplus：标普A+图额度
```

quota 列内的 JSON 默认单行省略展示；鼠标悬停时使用与表头问号一致的深色浮层、圆角和箭头，完整显示当前行的 JSON，较长内容自动换行，移出后关闭。

quota 支持结构化填写和 JSON 直填，两种方式共用以下校验，适用于个人配置及部门批量更新：

| 项目 | 规则 |
|---|---|
| 对象 | 非空 JSON 对象，至少包含一个字段。 |
| key | 以字母或下划线开头，仅含字母、数字、下划线，不允许重复。 |
| value | 非负整数，允许 0；不接受负数、小数、字符串等值，不新增业务额度上限。 |
| 数据保留 | 输入方式切换、保存和回显不能丢失字段或静默改变数字。 |
| 展示顺序 | 固定为 `total → scene → closeUpWhite → closeUp → sellPoint → aplus`，其他字段随后展示。 |

### 4. 新旧任务与异常处理

#### 新任务及人员调岗

先按第 3 节检查个人生图资格和额度，在首次真正提交外部生图请求时，按第 1 节关联实时查询当前部门，再按第 2 节匹配凭据。仅进入内部排队、尚未对外提交的任务，也在实际提交时执行这次查询。

员工的 `DepartmentID` 更新后，后续新任务按本次查到的新部门处理；未更新时仍按表中的原部门处理。本次查到的部门即为任务发起时的实际所属部门。

#### 已提交任务、重试与重新生成

任务首次提交时固定实际所属部门及使用的凭据，作为该任务的快照，并保留“发起时实际所属部门”与“使用哪个部门的凭据”的关联，便于核对费用归属。多个部门共用凭据时，两者仍应区分，具体记录方式由研发确定。

| 场景 | 处理规则 |
|---|---|
| 查询结果、轮询、同一外部任务失败重试或超时后继续查询 | 始终使用快照中的原凭据，避免重复生成和重复计费。 |
| 人员调岗、部门配置调整或旧配置停用 | 不改变已提交任务的部门与凭据快照；调整只影响后续新任务。 |
| 用户重新生成，实际创建新的外部任务 | 重新检查资格、额度和当前部门，再匹配凭据。 |
| 一个内部任务产生多个外部任务 | 每个外部任务均遵循上述查询、匹配和快照规则。 |
| 服务商已彻底撤销原凭据 | 明确反馈异常并支持人工处理，不能承诺仍可取回结果。 |

#### 历史任务过渡

按第 7 节分阶段上线时，以下新旧任务边界以各项目实际切换到部门凭据获取方式的时点为准；部门映射表单独上线不代表调用方已经切换。

- 本项目切换前已对外提交的任务，可在过渡期内继续按原方式查询，无需全量回填。
- 本项目切换后首次对外提交的任务必须遵循新规则，不能因缺少记录而误走历史路径；此前已进入内部排队、尚未对外提交的任务同样适用。
- 历史任务结束、相关依赖清理完成前，保留查询所需的原凭据及关联信息；业务页面移除相关入口，不等于可以同时删除其他项目或历史任务仍依赖的 appKey 字段。
- 极少量历史异常允许人工处理；原配置已删除或凭据已撤销时需明确异常，不宣称一定可恢复。

#### 部门与凭据异常

实际生图时出现以下异常，直接将任务判为失败，记录具体原因并结束处理，不得回退为旧个人凭据继续调用。

| 异常 | 错误原因示例 |
|---|---|
| 未获取到有效所属部门 | 未获取到用户所属部门 |
| 本部门及上级部门均无对应模型的有效凭据 | 所属部门及上级部门未配置 LinkFox 生图凭据（其他模型使用对应名称） |
| 部门配置冲突或凭据不可用 | 部门生图配置异常 / 生图凭据不可用 |

失败任务进入「已完成」，结果明确标记为失败，并可查看错误原因，不继续停留在处理中。「已完成」表示任务处理结束，不代表生成成功；错误信息仅描述原因，不包含实际凭据。

### 5. 管理页面查询与个人配置

美工、运营保持两个独立页面和各自配置范围，筛选、分页、查看、编辑、批量更新均限制在当前业务页面内。

列表与查询：

| 项目 | 规则 |
|---|---|
| 列表信息 | ID、用户ID、用户名、生图模型、quota、状态、更新时间、操作；quota 表头问号提示字段口径，文案见第 3 节。 |
| 移除项 | appKey 列、查询条件、查看、复制及编辑入口。 |
| 配置用户 | 复用可搜索的“全公司 → 各级部门 → 人员”树形多选，替换原完整用户名输入框。部门下可同时展示所属人员与下级部门，勾选部门联动选中该部门及下级范围内人员；勾选全公司选中树内全部候选人员。支持逐人调整、半选状态和清空，已选内容回填人员姓名，超出空间时按数量折叠。 |
| 组织数据 | 各级部门和人员读取现有组织数据，按当前父子关系及所属部门展示。【全公司】仅用于展示和联动选择，不作为员工的实际所属部门；异常部门沿用现有组织系统处理口径。 |
| 候选展示与权限 | 可进入页面的管理员看到一致的全公司候选树，不因查询数据权限不同额外裁剪。候选可见、可选不代表有权查到或修改该人员配置；实际查询与维护按第 7 节执行。 |
| 查询范围 | 按最终选中的人员查询当前业务页面已有配置；未选人员表示不限制人员条件。可选到未配置员工，查询无配置时显示空结果，不自动新增配置。 |
| 其他条件 | 查询条件依次为用户ID、配置用户、生图模型、启用状态；保留用户ID精确查询，与其他条件共同生效；重置清空查询条件。 |
| 排序与分页 | 更新时间倒序，同时间按 ID 倒序；默认 20 条，可选 20/50/100 条。 |

列表及新增、查看、编辑抽屉不展示部门信息，也不为这些展示场景新增部门路径查询。查询通过配置用户树按部门选人；按部门选人、批量更新及任务凭据匹配仍使用当前组织归属，个人额度配置不另存部门归属。

两处组织树中的搜索仅用于定位候选，不改变已选内容或节点的联动范围；搜索后勾选某部门，仍联动该部门完整范围内的人员或下级部门，不能仅按当前搜索可见项计算批量范围。

个人配置操作：

| 操作 | 规则 |
|---|---|
| 新增 | 填写用户ID、用户名、模型及 quota，默认启用；不填写生图凭据。用户ID口径见第 1 节；工号查询及用户信息回填沿用现有功能。 |
| 查看 | 展示配置 ID、用户ID、用户名、生图模型、quota JSON、启用状态及创建、更新时间。 |
| 编辑 | 用户ID、用户名、模型只读；可修改 quota 与启停状态。 |
| 删除 | 二次确认后仅删除当前用户在当前页面的该模型配置，其他配置不变。 |

部门缺失或未配置生图凭据时，允许先保存人员额度配置。保存不额外增加部门凭据预检、异常告警或阻断流程。实际生图发现异常，按第 4 节处理。

### 6. 按部门批量更新 quota

| 内容 | 规则 |
|---|---|
| 所属部门 | 必选，复用现有可搜索的部门树形多选，以全公司为根展示各级部门，支持同时选择多个部门或小组。勾选父部门联动选中下级；勾选全公司选中树内全部部门。取消、半选与祖先勾选状态遵循现有控件规则。 |
| 更新范围 | 按联动后最终勾选的部门集合匹配员工当前归属，重叠范围去重。半选节点本身不作为已选部门计入，其已勾选下级仍参与。 |
| 生图模型 | 由可选改为必选，默认显示“请选择”，只修改所选模型。 |
| quota | 必填，输入与校验见第 3 节，按完整对象覆盖。 |
| 提交 | 部门、模型及 quota 校验通过后，点击【提交】直接执行；处理中避免重复提交。 |
| 成功结果 | 提示更新成功，关闭抽屉并刷新当前列表。 |
| 无命中 | 提示“未命中任何记录”，保留输入，调整条件后可重试。 |

批量操作仅整份覆盖已有配置的 quota，不做字段合并；原 quota 中本次未填写的字段会被移除。命中范围包含启用和停用配置，但不改变启停、不修改人员归属，也不自动新增未配置员工。

批量范围由批量抽屉内的部门和模型独立确定，不受列表当前人员、用户ID、模型、状态筛选或分页限制；进入抽屉重新选择后提交。同一配置被多个联动节点覆盖时，只处理一次。

【全公司】为虚拟根节点，不计为实际部门；勾选后输入框显示“全公司”及已选部门数量，执行时按其联动选中的实际部门匹配配置。

未匹配有效所属部门的配置不计入部门批量范围，选择全公司时也不例外；仍可通过个人配置单独维护。

提交时按管理员配置页原有权限核对可操作配置，执行以当时最新的组织关系和权限为准。失败保留输入并明确提示，不能把失败或部分成功显示为全部成功；研发应在实现评审中说明最终失败处理方式。

例如：美工一组与二组共用同一凭据，选择一组只修改该组；IT 部与销售部共用凭据，选择销售部也不会同时修改 IT 部。

### 7. 权限与上线边界

- 仅已授权管理员可查看和维护配置。页面访问、实际查询、个人维护和批量执行均沿用管理员配置页原有菜单、按钮、服务端权限及既有特殊授权；保留已授权部门代表跨部门核对人员与额度的能力。配置用户与批量部门候选树均展示全公司组织结构，不按查询数据权限额外裁剪；选中候选项或全公司不扩大实际查询或操作权限。
- 控件复用只统一选择交互，额度配置的访问和维护仍按管理员配置页原有规则判断；已完成生图页面的图片可见权限继续按其原有规则执行。
- 本系统完成切换后，appKey 不出现在业务页面、页面数据、面向业务人员的接口、导出、普通日志和错误提示中，业务端旧写入入口同步关闭。过渡期内其他项目的服务端读取能力按下述顺序保留和退出，业务人员不获得凭据读取权限。
- 配置、启停及批量额度修改保留必要操作记录：谁、何时、修改了什么范围、结果如何。
- 各项目切换前确认使用中的模型和部门均能正确匹配，缺失项有明确处理结论；验证调岗后的新任务、调岗前任务的查询及重试。管理员配置页面另需验证原有权限、凭据入口移除、实际批量更新范围及结果。
- 过渡和回退均须保持已有任务的原凭据关联，不能重新引入跨部门使用错误凭据的问题。按下述顺序推进，具体发布安排、兼容期限、监测及回退实施由研发确定。

#### 跨项目依赖与上线顺序

对话生图项目目前依赖本系统用户配置表，按用户ID查询 appKey。本次需要对话生图项目与本系统同步推进凭据获取逻辑改造，按以下顺序上线：

| 阶段 | 上线内容 | 完成条件与边界 |
|---|---|---|
| 1. 部门映射表先上线 | 新的部门凭据映射表可以单独上线生产，并完成所需部门、模型的有效映射配置。 | 保留现有用户配置表的 appKey 字段及原有读取能力，保证尚未切换的项目继续运行；新增映射表本身不触发旧字段停用或删除。 |
| 2. 两个项目完成改造和切换 | 本系统与对话生图项目同步推进改造，各自完成生产发布和切换：按用户ID取得当前所属部门及模型，再按部门映射获取凭据；新任务及历史任务遵循第 4 节。 | 双方均完成生产切换并验证新任务生成、部门归属、已提交任务查询及重试。任一项目尚未切换完成，用户配置表的 appKey 及其必要读取能力继续保留。 |
| 3. 旧字段退出 | 确认双方生产代码均不再从用户配置表读取或写入 appKey 后，弃用该字段；满足清理条件时可直接删除。用户配置表继续承载用户授权、quota、启停等用户维度配置。 | 删除前确认历史任务和拟采用的回退方案不再依赖该字段；仍需使用的原凭据及关联已保留在可用的任务快照或其他受控记录中。关闭残留读写路径，验证两个项目均可正常运行。 |

旧字段退出以双方完成生产切换和验证为前提。弃用或删除用户配置表 appKey 时，部门映射及历史任务仍需使用的凭据继续保留；删除字段后的回退版本也不能再依赖该字段。

## 验收标准

以下 A01–A40 覆盖美工、运营两端及跨项目切换的适用场景。页面交互以“交互说明”及对应功能章节为准；组织查询、任务凭据、计费归属、项目切换与实际生图结果需由研发实现后验证，不能以静态原型演示代替验收。

| 编号 | 验收场景 | 预期结果 |
|---|---|---|
| A01 | 已授权用户的 `rb_admin.DepartmentID` 从 A 部更新为 B 部后，实际发起新任务 | 本次查询取得 B 部，新任务使用 B 部或其最近有效上级部门的对应模型凭据 |
| A02 | A 部发起的任务尚未完成，用户调到 B 部后查询结果 | 继续使用原凭据，调岗不影响查询 |
| A03 | 小组没有独立配置，提交新任务 | 使用最近一个有效上级部门配置 |
| A04 | 小组已有独立配置，提交新任务 | 优先使用小组配置 |
| A05 | 两个部门共用同一凭据，分别创建任务 | 均可生成，仍能区分各自实际发起部门 |
| A06 | IT 部借用销售部凭据，其子组提交任务 | 继承正确；未获用户授权者仍不可生图 |
| A07 | 用户配置不存在或已停用，尝试生图 | 拒绝提交，不因部门有配置而自动授权 |
| A08 | 用户额度不足，尝试生图 | 按现有额度规则拒绝 |
| A09 | 部门缺失，或本部门及上级部门均找不到有效配置，提交新任务 | 任务判失败，记录并展示具体原因，进入「已完成」且结果为失败；不继续处理中，不回退旧个人凭据 |
| A10 | 同部门在不同模型有各自配置，分别生成 | 使用对应模型凭据，不串用 |
| A11 | 同部门同模型出现两个有效配置 | 不允许形成有歧义的生图归属 |
| A12 | 更换部门凭据后，分别查询老任务和提交新任务 | 老任务沿用原凭据，新任务使用新凭据 |
| A13 | 旧部门配置停用后查询已有任务 | 停用本身不阻止已有任务使用原凭据 |
| A14 | 查看列表、筛选、详情、编辑及业务数据 | 均无法查看或写入完整 appKey |
| A15 | 配置用户树中勾选一个父部门后查询 | 联动选中该部门及下级范围内人员，输入框回填人员姓名；查询展示其中已有配置 |
| A16 | 整组选人后取消某个人，再查询 | 该人员不参与查询，其余已选人员保留；相应部门呈半选状态 |
| A17 | 同凭据下有多个小组，选择其中一组批量更新 | 只更新所选组的已有配置 |
| A18 | 打开批量抽屉并选择部门，未选模型时尝试提交；随后选择模型并填写有效 quota 后提交 | 模型默认显示“请选择”，未选时提示必选且不更新；校验通过后直接执行，成功提示并关闭抽屉、刷新列表，其他模型和另一业务页面配置不受影响 |
| A19 | 命中范围同时含启用、停用配置，更新 quota | 两者额度都更新，原启停不变 |
| A20 | 所选部门包含未配置的新员工，批量更新 | 仅更新范围内已有配置，不创建新员工配置 |
| A21 | 输入有效、无效及重复 key 的 quota 并切换输入方式 | 有效内容完整保留，无效内容被提示；提交按整份覆盖 |
| A22 | 首次提交超时后重试或查询同一任务 | 沿用原凭据，避免重复生成及计费 |
| A23 | 本项目切换前已提交任务仍未完成，继续查询 | 按过渡方案处理，保留原凭据查询能力，无需全量回填 |
| A24 | 本项目切换后首次对外提交的任务丢失所需凭据关联 | 明确异常，不误按历史任务回退 |
| A25 | 数据权限不同的已授权管理员查看两处组织树并查询、维护，未授权人员尝试访问或修改 | 已授权管理员看到一致的全公司候选树；实际查询和维护范围沿用管理员配置页原权限且看不到凭据。未授权人员按原权限被拒绝，候选可见或可选不增加配置权限 |
| A26 | 核查两个共用凭据部门的任务 | 可区分实际发起部门、凭据归属部门和模型 |
| A27 | 生图用户ID对应的员工归属 A 部且兼管 B 部，按部门选人和批量更新 | 通过 `userId = rb_admin.ID` 取得 A 部；该员工按 A 部归属参与范围计算，不因兼管而成为 B 部所属人员 |
| A28 | 部门缺失或未配置生图凭据，填写符合现有校验的人员额度配置并保存 | 保存成功，不因部门或凭据异常增加告警、预检或阻断；后续生图异常按 A09 处理 |
| A29 | 员工已调岗但表内归属仍为 A 部，随后将 `rb_admin.DepartmentID` 更新为 B 部；分别实际发起新任务 | 更新前按查询到的 A 部处理，更新后按查询到的 B 部处理；此前已提交任务继续使用原快照 |
| A30 | 任务进入内部排队后、首次对外提交前，将员工归属从 A 部更新为 B 部 | 实际提交时实时查询取得 B 部并匹配凭据，任务快照记录 B 部及实际使用的凭据 |
| A31 | 分别打开美工、运营列表及新增、查看、编辑抽屉，再通过配置用户树按部门查询 | 列表和个人配置抽屉不展示部门字段；部门树仍可选人并筛选配置，个人配置不保存部门归属 |
| A32 | 查询选择未配置员工，随后清空人员或重置条件 | 未配置员工显示空结果且不新增配置；清空后恢复相应查询范围，用户ID、模型和状态与人员条件共同生效 |
| A33 | 批量选择多个部门及有父子重叠的范围，再取消部分下级并提交 | 按最终勾选集合更新；半选父节点本身不计入，每条命中配置只更新一次 |
| A34 | 列表已筛选某个人、模型或启用状态并分页，随后打开批量配置并提交 | 按抽屉内重新选择的部门和模型直接执行；包含范围内停用配置，不受列表条件或分页限制 |
| A35 | 配置用户或批量部门输入搜索词、展开及收起分支、勾选父部门、清除搜索词并核对范围，最后清空选择 | 搜索保留可辨识的组织层级，分支可展开及收起，不清除已选项或截断父部门的完整联动范围；半选状态正确。清空选择后取消已选项，批量未选择部门时不能提交 |
| A36 | 组织新增首级或下级部门、调整层级或人员归属后重新读取组织树，并分别勾选全公司 | 两处树展示更新后的组织结构；人员树选中全部候选人员，部门树选中全部实际部门。批量输入框显示“全公司”及实际已选部门数，虚拟节点不计入部门数；执行按实际部门去重，仍受当前业务、模型及原有权限约束 |
| A37 | 当前业务存在未匹配部门的配置，勾选全公司并选择其模型批量更新 | 未匹配部门的配置不计入批量更新范围，额度、启停均保持不变，仍可通过个人配置维护 |
| A38 | 部门映射表单独上线，两个项目尚未切换 | 映射表可用，现有用户配置表 appKey 及原有读取能力保留；两个项目原有业务继续运行 |
| A39 | 本系统与对话生图项目中，仅一方完成生产切换 | 已切换方的新任务使用部门映射，另一方仍可沿用原有读取方式；旧 appKey 字段不提前弃用或删除，双方历史任务查询不受影响 |
| A40 | 双方完成生产切换并验证，拟弃用或删除用户配置表 appKey | 确认双方生产代码、历史任务及回退方案不再依赖旧字段后退出；两个项目的新任务和已有任务查询正常，所需部门凭据及历史凭据仍可用 |
